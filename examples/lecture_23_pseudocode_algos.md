# Lecture 23: Algorithms for Hidden Markov Models (Pseudocode)

This document walks through the key algorithms used in `lecture_23.R` for inference in a **2-state Hidden Markov Model (HMM) with Normal emissions**. All algorithms are presented in the context of that specific example.

---

## Setup and Notation

**The model:**

We observe a sequence of data points $Y_1, Y_2, \dots, Y_n$ (here $n = 100$). Each observation is generated by one of $m = 2$ hidden states $X_1, X_2, \dots, X_n$. The hidden states form a Markov chain -- the current state depends only on the previous state.

**Parameters:**

| Symbol                 | Meaning                          | True value in `lecture_23.R` |
| ---------------------- | -------------------------------- | ---------------------------- |
| $\mu = (\mu_1, \mu_2)$ | Emission means (one per state)   | $(3, 5)$                     |
| $\nu$                  | Transition matrix ($m \times m$) | see table below              |
| $\pi = (\pi_1, \pi_2)$ | Initial state probabilities      | $(0.5, 0.5)$                 |

**Emission model:** If the hidden state at time $t$ is $X_t = j$, then the observation is drawn from a Normal distribution:

$$Y_t \mid X_t = j \sim \text{Normal}(\mu_j, \sigma^2 = 1)$$

**Transition model:** The probability of moving from state $j$ to state $k$ is:

$$P(X_t = k \mid X_{t-1} = j) = \nu_{j,k}$$

The transition matrix $\nu$ for this example:

|                  | To State 1 | To State 2 |
| ---------------- | ---------- | ---------- |
| **From State 1** | 0.9        | 0.1        |
| **From State 2** | 0.1        | 0.9        |

The high diagonal values (0.9) mean the chain tends to stay in whichever state it's in -- it's "sticky."

## Algorithm 1: The Viterbi Algorithm

### Purpose

The Viterbi algorithm finds the **single most likely sequence** of hidden states given the observed data and known parameters. Think of it as asking: "If I had to make one best guess for the entire sequence of states, what would it be?"

This is different from finding the most likely state at each individual time point -- Viterbi finds the most likely _path_ through all time points simultaneously.

### Inputs

- Observations: $Y_1, \dots, Y_n$
- Parameters: $\mu$, $\nu$, $\pi$ (assumed known / set to true values)

### Output

- $\hat{X}_1, \dots, \hat{X}_n$: the most likely state sequence

### Key idea

We build up a table $\delta$ where $\delta[t, i]$ stores the probability of the **best path** that ends in state $i$ at time $t$. We fill this table left-to-right (forward in time), then trace back to recover the best path.

> **Note:** In practice, these probabilities can become extremely small for long sequences (products of many numbers less than 1). A common improvement is to work in log-space, replacing products with sums of logs. The lecture code uses raw probabilities for clarity, which works fine for $n = 100$.

### The delta table

The $\delta$ table has $n$ rows (one per time step) and $m$ columns (one per state):

| Time     | State 1       | State 2       |
| -------- | ------------- | ------------- |
| $t = 1$  | $\delta[1,1]$ | $\delta[1,2]$ |
| $t = 2$  | $\delta[2,1]$ | $\delta[2,2]$ |
| $\vdots$ | $\vdots$      | $\vdots$      |
| $t = n$  | $\delta[n,1]$ | $\delta[n,2]$ |

### Pseudocode

```
VITERBI(Y, pi, nu, mu):

    # --- Step 1: Initialization (fill first row of delta) ---
    for each state i in {1, 2}:
        delta[1, i] = pi[i] * NormalDensity(Y[1], mu[i])
        # "probability of starting in state i" * "probability of seeing Y[1] from state i"

    # --- Step 2: Recursion (fill remaining rows, left to right) ---
    for t = 2 to n:
        for each state i in {1, 2}:
            # Consider all possible previous states j
            # and find which one gives the highest probability path to state i at time t
            for each previous state j in {1, 2}:
                candidate[j] = delta[t-1, j] * nu[j, i] * NormalDensity(Y[t], mu[i])
                #               ^^^^^^^^^^^^   ^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^^
                #               best path      transition  emission probability
                #               prob to j      j -> i      of Y[t] from state i
                #               at t-1

            delta[t, i] = max(candidate)   # keep only the best incoming path

    # --- Step 3: Traceback (recover the best path, right to left) ---
    Xhat[n] = argmax over i of delta[n, i]   # best final state

    for t = (n-1) down to 1:
        for each state j in {1, 2}:
            score[j] = delta[t, j] * nu[j, Xhat[t+1]]
            #          ^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^
            #          best path     transition from j
            #          prob to j     to the already-chosen
            #          at time t     next state

        Xhat[t] = argmax over j of score[j]

    return Xhat
```

### Worked example of the delta table filling

Suppose at time $t = 5$, we have already computed:

| Time    | State 1               | State 2               |
| ------- | --------------------- | --------------------- |
| $t = 5$ | $\delta[5,1] = 0.003$ | $\delta[5,2] = 0.007$ |

Now we want to fill in $\delta[6, 1]$ (the best path probability ending in State 1 at $t = 6$):

- **Coming from State 1:** $0.003 \times \nu_{1,1} \times f(Y_6 \mid \mu_1) = 0.003 \times 0.9 \times f(Y_6 \mid \mu_1)$
- **Coming from State 2:** $0.007 \times \nu_{2,1} \times f(Y_6 \mid \mu_1) = 0.007 \times 0.1 \times f(Y_6 \mid \mu_1)$

We take whichever is larger as $\delta[6, 1]$. The same logic applies for $\delta[6, 2]$.

## Algorithm 2: Forward-Backward Sampling (FFBS)

### Purpose

While Viterbi gives us a single "best guess" path, Forward-Backward Sampling (also called Forward Filtering Backward Sampling, or FFBS) lets us **draw random samples** of the hidden state sequence from its full conditional distribution. This is a building block of the Gibbs sampler -- each iteration of the sampler uses FFBS to get a new sample of the hidden states.

The key difference from Viterbi: instead of taking the max at each step, we **sum** over all paths (forward pass), and then **sample** states proportionally to their probabilities (backward pass).

### Inputs

- Observations: $Y_1, \dots, Y_n$
- Current parameter values: $\mu$, $\nu$, $\pi$ (these change each Gibbs iteration)

### Output

- One sampled state sequence: $X_1, \dots, X_n$

### The alpha table

Just like the delta table in Viterbi, the $\alpha$ table has $n$ rows and $m$ columns. But instead of storing the _best_ path probability, $\alpha[t, i]$ stores the _total_ probability of all paths that end in state $i$ at time $t$:

| Time     | State 1       | State 2       |
| -------- | ------------- | ------------- |
| $t = 1$  | $\alpha[1,1]$ | $\alpha[1,2]$ |
| $t = 2$  | $\alpha[2,1]$ | $\alpha[2,2]$ |
| $\vdots$ | $\vdots$      | $\vdots$      |
| $t = n$  | $\alpha[n,1]$ | $\alpha[n,2]$ |

### Pseudocode

```
FORWARD_BACKWARD_SAMPLE(Y, pi, nu, mu):

    # ============================================
    # FORWARD PASS: Fill the alpha table
    # ============================================

    # --- Initialization ---
    for each state i in {1, 2}:
        alpha[1, i] = pi[i] * NormalDensity(Y[1], mu[i])

    # --- Recursion ---
    for t = 2 to n:
        for each state i in {1, 2}:
            for each previous state j in {1, 2}:
                candidate[j] = alpha[t-1, j] * nu[j, i] * NormalDensity(Y[t], mu[i])

            alpha[t, i] = SUM(candidate)    # <-- SUM, not MAX (this is the key difference from Viterbi)

    # ============================================
    # BACKWARD PASS: Sample states right-to-left
    # ============================================

    # --- Sample the last state ---
    prob_vec = alpha[n, ] / sum(alpha[n, ])       # normalize to get probabilities
    X[n] = sample from {1, 2} with probabilities prob_vec

    # --- Sample remaining states going backward ---
    for t = (n-1) down to 1:
        for each state i in {1, 2}:
            prob_vec[i] = alpha[t, i] * nu[i, X[t+1]]
            #             ^^^^^^^^^^^   ^^^^^^^^^^^^^^
            #             forward prob   transition to
            #             of being in    the already-sampled
            #             state i        next state

        prob_vec = prob_vec / sum(prob_vec)         # normalize
        X[t] = sample from {1, 2} with probabilities prob_vec

    return X
```

### Why forward then backward?

- **Forward pass:** At each time step, $\alpha[t, i]$ accumulates evidence from _all observations up to time $t$_. After the forward pass, $\alpha[n, i]$ reflects the entire observed sequence.
- **Backward pass:** We sample states from right to left. When sampling $X_t$, we already know $X_{t+1}$ (we just sampled it). Combining $\alpha[t, i]$ (evidence from the left) with $\nu[i, X_{t+1}]$ (consistency with the next state) gives us the correct conditional probability for $X_t$.

This two-pass approach is what makes it possible to draw _exact_ samples from the conditional distribution $P(X_1, \dots, X_n \mid Y, \mu, \nu, \pi)$.

## Algorithm 3: Gibbs Sampler for the Full HMM Posterior

### Purpose

The Gibbs sampler is the main algorithm. It lets us approximate the **full posterior distribution** of all unknown quantities -- the hidden states _and_ the parameters -- given the observed data. Unlike Viterbi (which gives one best guess) or a single FFBS pass (which samples states for fixed parameters), the Gibbs sampler iteratively updates everything: states, transition probabilities, initial probabilities, and emission means.

After enough iterations, the samples approximate draws from the joint posterior:

$$P(\mu, \nu, \pi, X_{1:n} \mid Y_{1:n})$$

### Inputs

- Observations: $Y_1, \dots, Y_n$
- Initial guesses for parameters: $\mu^{(0)}, \nu^{(0)}, \pi^{(0)}$
- Number of MCMC iterations: `numsamp` (= 10,000 in the code)

### Output

- Posterior samples of all parameters and hidden states across iterations

### How the Gibbs sampler works (high level)

The idea behind Gibbs sampling is: even though we can't sample from the complicated joint posterior directly, we _can_ sample from each parameter's **full conditional distribution** (its distribution given everything else held fixed). By cycling through all parameters and sampling each one in turn, the samples eventually converge to draws from the joint posterior.

Each iteration of the Gibbs sampler has four blocks:

```
                    +-------------------------------------+
                    |         One Gibbs Iteration          |
                    +-------------------------------------+
                    |                                       |
                    |  1. Sample hidden states X            |
                    |     (using FFBS, given current        |
                    |      mu, nu, pi)                      |
                    |              |                        |
                    |              v                        |
                    |  2. Sample transition matrix nu       |
                    |     (given current X)                 |
                    |              |                        |
                    |              v                        |
                    |  3. Sample initial distribution pi    |
                    |     (given current X)                 |
                    |              |                        |
                    |              v                        |
                    |  4. Sample emission means mu          |
                    |     (given current X and Y)           |
                    |                                       |
                    +-------------------------------------+
                                   |
                          Repeat numsamp times
```

### Pseudocode

```
GIBBS_SAMPLER(Y, numsamp):

    # --- Initialize parameters ---
    cur_nu = initial guess for transition matrix     # e.g., ((0.75, 0.25), (0.25, 0.75))
    cur_pi = initial guess for initial distribution  # e.g., (0.5, 0.5)
    cur_mu = initial guess for emission means        # e.g., (2, 4)

    for iter = 1 to numsamp:

        # ================================================
        # BLOCK 1: Sample hidden states via FFBS
        # ================================================
        cur_X = FORWARD_BACKWARD_SAMPLE(Y, cur_pi, cur_nu, cur_mu)
        # (see Algorithm 2 above)

        # ================================================
        # BLOCK 2: Sample transition matrix (nu)
        # ================================================

        # Step 2a: Count transitions in the current state sequence
        # Build an m x m count matrix N where N[j,k] = number of times
        # the chain transitions from state j to state k

        Initialize N as an m x m matrix of zeros
        for t = 2 to n:
            j = cur_X[t-1]    # state we came from
            k = cur_X[t]      # state we went to
            N[j, k] = N[j, k] + 1

        # Example N matrix after counting (hypothetical):
        #
        #        To State 1  To State 2
        # From 1     42          5
        # From 2      6         46
        #
        # (High diagonal counts reflect sticky transitions)

        # Step 2b: Sample each row of nu from a Dirichlet distribution
        # Prior: Dirichlet(1, 1) on each row (uniform prior)
        # Posterior: Dirichlet(N[j,1] + 1, N[j,2] + 1) for row j
        #
        # The Dirichlet is sampled via the Gamma trick:
        #   draw g_k ~ Gamma(N[j,k] + 1, 1) for each k
        #   normalize: nu[j,k] = g_k / sum(g)

        for each row j in {1, 2}:
            for each column k in {1, 2}:
                cur_nu[j, k] = draw from Gamma(shape = N[j,k] + 1, rate = 1)
            cur_nu[j, ] = cur_nu[j, ] / sum(cur_nu[j, ])   # normalize row to sum to 1

        # ================================================
        # BLOCK 3: Sample initial distribution (pi)
        # ================================================

        # Count how many observations are assigned to each state
        for each state j in {1, 2}:
            state_count[j] = number of times cur_X[t] == j (over all t)

        # Sample pi from Dirichlet posterior (same Gamma trick)
        for each state j in {1, 2}:
            cur_pi[j] = draw from Gamma(shape = state_count[j] + 1, rate = 1)
        cur_pi = cur_pi / sum(cur_pi)   # normalize

        # ================================================
        # BLOCK 4: Sample emission means (mu)
        # ================================================

        # For each state j, the observations assigned to that state
        # are Y[t] where cur_X[t] == j.
        #
        # With a flat (improper) prior on mu_j and known variance sigma^2 = 1,
        # the full conditional is:
        #
        #   mu_j | rest ~ Normal(mean = Y_bar_j, variance = 1 / n_j)
        #
        # where Y_bar_j = mean of Y values in state j
        #       n_j     = number of observations in state j

        for each state j in {1, 2}:
            n_j = number of observations where cur_X[t] == j

            if n_j > 0:
                Y_bar_j = mean of Y[t] where cur_X[t] == j
                cur_mu[j] = draw from Normal(mean = Y_bar_j, sd = sqrt(1 / n_j))
            else:
                cur_mu[j] = keep previous value   # avoid NaN from empty state

        # ================================================
        # Store samples from this iteration
        # ================================================
        X_samples[iter, ]  = cur_X
        nu_samples[iter, ] = cur_nu (flattened to a vector)
        pi_samples[iter, ] = cur_pi
        mu_samples[iter, ] = cur_mu

    return X_samples, nu_samples, pi_samples, mu_samples
```

### Why does this work?

Each block samples one group of unknowns from its **full conditional distribution** -- i.e., the distribution of that parameter given all the other parameters and the data, all held fixed. The theory of Gibbs sampling guarantees that cycling through these blocks will eventually produce samples from the correct joint posterior, regardless of where we start (though it may take many iterations to "forget" bad starting values -- see burn-in below).

## Algorithm 4: Post-Processing the MCMC Output

### Purpose

Raw MCMC output isn't immediately usable. We need to handle three issues before drawing conclusions:

1. **Label switching** -- the sampler can swap which state is "1" and which is "2"
2. **Burn-in** -- early samples reflect starting values, not the posterior
3. **Autocorrelation / thinning** -- consecutive samples are correlated

### 4a: Fixing Label Switching

**The problem:** The HMM has a symmetry. A model with $\mu_1 = 3, \mu_2 = 5$ and states labeled one way is identical to a model with $\mu_1 = 5, \mu_2 = 3$ and states labeled the opposite way. The Gibbs sampler can freely jump between these two modes during sampling, which causes the marginal posteriors to look bimodal (a mix of both labelings) rather than concentrated around the true values.

**The fix:** Enforce a consistent ordering. The code uses the convention $\mu_1 < \mu_2$. Whenever a sample has $\mu_1 > \mu_2$, we swap everything to restore the ordering.

```
FIX_LABEL_SWITCHING(mu_samples, nu_samples, pi_samples, X_samples):

    for each iteration i:
        if mu_samples[i, 1] > mu_samples[i, 2]:

            # Swap the emission means
            swap mu_samples[i, 1] and mu_samples[i, 2]

            # Swap the initial probabilities
            swap pi_samples[i, 1] and pi_samples[i, 2]

            # Swap the transition matrix
            # Original: | nu_11  nu_12 |    After swap: | nu_22  nu_21 |
            #           | nu_21  nu_22 |                | nu_12  nu_11 |
            #
            # The rows and columns are both permuted because both the
            # "from" and "to" state labels are being swapped.
            swap nu_samples[i] appropriately (rows and columns permuted)

            # Relabel the hidden states
            everywhere cur_X == 1, set it to 2 (and vice versa)

    return corrected samples
```

**Before vs. After label switching fix:**

|                | $\mu_1$ samples            | $\mu_2$ samples            |
| -------------- | -------------------------- | -------------------------- |
| **Before fix** | Mix of values near 3 and 5 | Mix of values near 3 and 5 |
| **After fix**  | Concentrated around 3      | Concentrated around 5      |

### 4b: Burn-in Removal

**The problem:** The sampler starts from arbitrary initial values (e.g., $\mu = (2, 4)$). The early samples are still "finding their way" to the high-probability region of the posterior and don't represent the true posterior.

**The fix:** Discard the first $B$ samples. The code uses $B = 1000$ (out of 10,000 total), keeping samples 1001 through 10,000.

```
REMOVE_BURNIN(samples, B = 1000):
    return samples[B+1 : end, ]
```

**How to choose $B$:** Look at trace plots (parameter value vs. iteration number). The burn-in period is the initial stretch where the chain is visibly trending or drifting. Once the trace plot looks like stable noise around a constant level, burn-in is over. Running multiple chains from different starting values helps confirm this -- when they overlap, they've converged.

### 4c: Thinning

**The problem:** Consecutive MCMC samples are correlated (sample 501 is similar to sample 500). This autocorrelation means that 9,000 post-burn-in samples don't contain as much independent information as 9,000 truly independent draws would.

**The fix:** Keep only every $k$-th sample. The code uses $k = 5$, keeping every 5th sample.

```
THIN(samples, k = 5):
    keep indices k, 2k, 3k, ...
    return samples[kept_indices, ]
```

**How to choose $k$:** Look at the autocorrelation function (ACF) plots. If the ACF drops to near zero by lag $k$, then thinning by $k$ gives approximately independent samples.

### 4d: Combining Multiple Chains

The code runs the Gibbs sampler twice with different starting values. After fixing label switching and removing burn-in from each chain independently, the post-burn-in samples are stacked together. This increases the effective sample size and provides a convergence check: if both chains give similar results, we have more confidence the sampler has converged.

```
COMBINE_CHAINS(chain1_samples, chain2_samples):
    return stack chain1_samples on top of chain2_samples (row-bind)
```

**Summary of the post-processing pipeline:**

| Step                 | What it does                     | Before                   | After                                   |
| -------------------- | -------------------------------- | ------------------------ | --------------------------------------- |
| Label switching fix  | Enforce $\mu_1 < \mu_2$ ordering | 10,000 samples per chain | 10,000 samples per chain (relabeled)    |
| Burn-in removal      | Discard first 1,000 iterations   | 10,000 samples per chain | 9,000 samples per chain                 |
| Combine chains       | Stack the two chains             | 9,000 samples x 2 chains | 18,000 samples total                    |
| Thinning (every 5th) | Reduce autocorrelation           | 18,000 samples           | 3,600 approximately independent samples |

## Algorithm 5: Computing Posterior State Probabilities

### Purpose

After all the post-processing, we have a collection of sampled state sequences. For each time point $t$, we can estimate the **posterior probability** that the hidden state is in State 2 (or State 1) by simply counting what fraction of our samples assigned that time point to each state.

This gives a more nuanced picture than Viterbi's single best guess -- instead of just "State 1" or "State 2," we get a probability like "85% chance of being in State 2."

### Inputs

- Post-processed state samples: $X^{(1)}, X^{(2)}, \dots, X^{(S)}$ (each is a length-n sequence)

### Output

- $P(X_t = 2 \mid Y)$ for each time point $t = 1, \dots, n$

### Pseudocode

```
POSTERIOR_STATE_PROBS(X_samples):

    S = number of posterior samples (rows of X_samples)

    for each time point t = 1 to n:
        post_prob[t] = (number of samples where X[t] == 2) / S

    return post_prob
```

A posterior probability near 1.0 means we're very confident the system was in State 2 at that time; near 0.0 means confident in State 1; near 0.5 means we're uncertain.

```
Observed data Y
       |
       v
+----------------------------------------------+
|  Viterbi Algorithm                           |
|  (uses known/true parameters)                |
|  --> Single best state sequence              |
+----------------------------------------------+
       |
       v
+----------------------------------------------+
|  Gibbs Sampler (run twice, different starts) |
|                                              |
|    Each iteration:                           |
|      1. FFBS  -->  sample states             |
|      2. Dirichlet  -->  sample transitions   |
|      3. Dirichlet  -->  sample initial dist  |
|      4. Normal  -->  sample emission means   |
|                                              |
|  --> 10,000 samples of (X, nu, pi, mu) x 2  |
+----------------------------------------------+
       |
       v
+----------------------------------------------+
|  Post-Processing                             |
|    1. Fix label switching (per chain)        |
|    2. Remove burn-in (first 1,000)           |
|    3. Combine chains                         |
|    4. Thin (every 5th sample)                |
|  --> ~3,600 clean posterior samples           |
+----------------------------------------------+
       |
       v
+----------------------------------------------+
|  Posterior Inference                          |
|    - Posterior state probabilities            |
|    - Posterior means/credible intervals       |
|      for mu, nu, pi                          |
+----------------------------------------------+
```
